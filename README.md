# مانیتور شبکه (NetMonitor)

اپلیکیشن اندرویدی نمونه که دو کار انجام می‌دهد:

1. **مصرف اینترنت هر برنامه** — با استفاده از `NetworkStatsManager` (بدون نیاز به روت).
2. **دامنه‌هایی که هر برنامه به آن‌ها وصل می‌شود** — با راه‌اندازی یک VPN محلی روی خود گوشی که فقط پرسش‌های DNS را می‌خواند و دامنه هر پرسش را به برنامه صاحب آن (uid) نسبت می‌دهد. ترافیک شما به هیچ سروری در اینترنت ارسال نمی‌شود؛ همه‌چیز محلی و روی خود گوشی پردازش می‌شود.

## نحوه باز کردن پروژه

1. پوشه `NetMonitor` را از حالت zip خارج کنید.
2. Android Studio (نسخه Koala یا جدیدتر پیشنهاد می‌شود) را باز کنید → `Open` → پوشه `NetMonitor` را انتخاب کنید.
3. صبر کنید تا Gradle Sync تمام شود (اولین بار نیاز به دانلود Gradle 8.7 و SDK 34 دارد، به اینترنت نیاز است).
4. یک گوشی یا شبیه‌ساز با Android 8 (API 26) به بالا وصل کنید و Run بزنید.

> اگر Android Studio بگوید Gradle Wrapper کامل نیست، از منوی `File > Sync Project with Gradle Files` استفاده کنید یا با کلیک راست روی `gradlew` اجازه دهید Android Studio آن را بازسازی کند.

## نحوه استفاده در گوشی

### تب «مصرف داده»
- بار اول باید دکمه «رفتن به تنظیمات دسترسی» را بزنید و در صفحه‌ای که باز می‌شود، به این اپلیکیشن دسترسی **Usage Access** را فعال کنید (این یک تنظیم استاندارد اندروید است، نه مجوز خطرناک).
- بعد از برگشتن به اپ، لیست برنامه‌ها به‌همراه حجم دانلود/آپلود هر کدام در بازه امروز/۷ روز/۳۰ روز نمایش داده می‌شود.

### تب «دامنه‌ها»
- دکمه «شروع رصد دامنه‌ها» را بزنید. اندروید یک پنجره تایید VPN نشان می‌دهد (چون از API رسمی `VpnService` استفاده می‌شود) — تایید کنید.
- از این لحظه، هر بار برنامه‌ای در گوشی یک دامنه را resolve کند (یعنی تقریباً هر بار که به یک سرور وصل می‌شود)، آن دامنه ثبت و زیر نام برنامه مربوطه نمایش داده می‌شود.
- نسبت‌دادن دقیق دامنه به برنامه (uid) فقط از Android 10 (API 29) به بالا کار می‌کند؛ روی نسخه‌های قدیمی‌تر دامنه‌ها با برچسب «نامشخص» ثبت می‌شوند.
- دکمه «توقف رصد» را بزنید تا VPN خاموش شود.

## محدودیت‌های شناخته‌شده و نکات فنی

- این پیاده‌سازی فقط ترافیک **DNS (پورت 53)** را از تونل VPN عبور می‌دهد (نه کل ترافیک اینترنت)، به همین دلیل اینترنت گوشی در حین رصد کاملاً عادی کار می‌کند. این دقیقاً همان روشی است که اپ‌هایی مثل DNS66 استفاده می‌کنند.
- اگر برنامه‌ای دامنه‌ای را قبلاً در حافظه سیستم‌عامل کش کرده باشد (DNS cache)، ممکن است دوباره پرسش DNS نفرستد و در نتیجه در لیست دیده نشود.
- بعضی برنامه‌ها (مثل مرورگرهایی با DNS-over-HTTPS داخلی) پرسش‌های DNS خود را رمزنگاری‌شده و مستقیم به سرورهای خودشان می‌فرستند و ممکن است از این روش عبور کنند. برای رصد کامل آن‌ها نیاز به تحلیل ترافیک TLS (فیلد SNI) و ساخت یک NAT/proxy کامل‌تر است که پیچیدگی بسیار بیشتری دارد (مشابه پروژه متن‌باز NetGuard).
- برای انتشار عمومی در Google Play، اپلیکیشن‌هایی که از VPN برای رصد ترافیک استفاده می‌کنند باید سیاست حریم خصوصی روشن داشته باشند و کاربر را دقیق مطلع کنند.

## ساختار پروژه

```
app/src/main/java/com/example/netmonitor/
├── MainActivity.kt          // رابط کاربری Compose (دو تب)
├── MainViewModel.kt         // مدیریت state و ارتباط با دیتابیس/آمار
├── data/
│   ├── AppUsageInfo.kt      // مدل مصرف داده هر برنامه
│   └── DomainConnection.kt  // Entity/DAO/Database برای دامنه‌های ثبت‌شده (Room)
├── util/
│   └── UsageStatsHelper.kt  // خواندن NetworkStatsManager
└── vpn/
    ├── LocalVpnService.kt   // سرویس VpnService و منطق رله DNS
    └── DnsPacketUtils.kt    // پارس/ساخت پکت‌های IPv4+UDP+DNS
```
